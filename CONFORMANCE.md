# WCAG 2.2 AA self-assessment — not a conformance claim

## Accessibility implementation update — 2026-11-21

The learner component now includes keyboard answer/source skip links, an explicit `aria-expanded` state for lesson suggestions, answer and source focus targets, `lang`/`dir` propagation for the component and messages, descriptive source names, a simple-language toggle when a shorter answer is supplied, visible transcript/voice-stop states, and text-based tutor handoff status with ticket codes. Playwright coverage was added for keyboard navigation, answer/source announcements, simple-language switching, Arabic direction, and text handoff.

These changes are implementation evidence only. NVDA, TalkBack, VoiceOver, braille display, deaf/hard-of-hearing co-designer review, fluent-speaker review, physical speech devices, actual 200%/400% zoom, and live SMS/Telegram/phone delivery remain unverified. The gate stays **NOT VERIFIED**.

Follow-up implementation also adds visible tutor lifecycle status, focus restoration for nested forms, multiple-source grouping, optional vibration alongside text state, a repository media-caption check, and higher-contrast Savanna page accents. These changes do not replace human assistive-technology or co-designer testing.

The embeddable component now also includes an opt-in browser-only Voice guide. It uses the local Web Speech API only, is off by default, has an Alt+V toggle, debounced accessible-name/role/state focus feedback, local speech rate/volume/voice settings, visible captions with pin/dismiss controls, stop/pause/resume controls, language-matched voices, and a visible text fallback when a matching voice is unavailable. The guide reuses the component's existing polite screen-reader announcement channel; it does not add a second live announcement channel. Automated Playwright coverage mocks the browser speech API for toggle persistence, focus narration, cancellation, captions, and missing-voice fallback. Real screen readers, device voices, and physical audio remain unverified.

This is a code-based self-assessment, not an independent accessibility audit or a claim of full WCAG conformance. “Supports” describes the feature as implemented in the repository; the whole product still needs manual testing with the target browsers, devices, and assistive technologies.
